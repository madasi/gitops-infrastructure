# 2026-11-13

## 🎯 Focus / Goals
* Enable secure remote access to the home LAN through `pve-dell01` as a Tailscale subnet router.
* Catch the GitLab copy of the repository up with GitHub after recent merges.

## 🛠️ Changes & Automation
* **Proxmox/Nodes:** Verified Tailscale connectivity to `pve-dell01` at `100.80.250.43` from the away network (`10.160.0.80`). The laptop's network did not overlap the home subnet (`192.168.1.0/24`).
* **Ansible/Tofu:** Applied `configure-tailscale-ip-forwarding.yaml` to persist `net.ipv4.ip_forward=1` on `pve-dell01`. The check run predicted a change, the apply reported `changed=1`, and the follow-up run reported `changed=0`. Confirmed access to `dns-primary` (`192.168.1.53`) over the subnet route with three successful pings and no packet loss.
* **Secrets/SOPS:** Enabled the `community.sops.sops` vars plugin locally so Ansible could load the encrypted sudo credential. The age key stayed on the local controller; no secret values were shared.
* **Git/Repo:** Compared GitHub `main` with GitLab `main`; GitLab had no unique commits and was 13 commits behind. Fast-forwarded GitLab to the GitHub tip with an explicit, non-force push. The local `origin` remote fetches from GitHub and has push URLs for both providers, so GitHub PR merges alone do not update GitLab.
    
## 🚧 Blockers & Troubleshooting
* Initial Ansible SSH connection used the inventory's LAN address and failed off-network. Overrode the host address with the Tailscale IP and used `HostKeyAlias=192.168.1.40` to validate against the already trusted SSH host key. Ansible then connected using its inventory SSH key.
* The first privileged check failed because the SOPS vars plugin had been disabled for that shell, so the sudo credential was unavailable. Re-enabling the plugin resolved this.

## 📝 Decisions (ADRs)
* Treat successful connectivity to `192.168.1.53` as verification that route advertisement, approval, and the current tailnet policy permit this laptop's traffic. No separate policy change was needed for the tested ICMP path.
* Keep GitHub as the canonical repository. Decide whether to set up GitLab-side pull mirroring (if available on the plan) or use an explicit manual sync after GitHub merges; avoid bidirectional mirroring.

## ⏭️ Next Steps
* Test the actual home services needed remotely, not only ICMP to `dns-primary`.
* Choose and document a repeatable GitHub-to-GitLab sync method. Consider removing GitLab as an extra push URL from local `origin` and using a separately named remote for intentional manual syncs.
* Review the Tailscale router playbook and checklist on `feat/tailscale-subnet-router` and complete its PR workflow if still outstanding.
